# Такси — лабораторная работа на Flutter

Два приложения с настоящей картой Иркутска, геолокацией устройства и общим учебным HTTP-сервером. API-ключи и платные сервисы не нужны.

## Структура

- `taxi-customers` — клиент: подача и назначение, три тарифа, цена, создание и отмена заказа, текущий статус, история.
- `taxi-driver` — водитель: выход на линию, список заказов, принятие, маршрут до клиента, прибытие, начало и завершение поездки, история и сумма заработка.
- `packages/taxi_shared` — модели, расчёт тарифов, карта, геолокация, маршруты, HTTP-клиент и контроллер.
- `server/bin/server.dart` — сервер на стандартной библиотеке Dart, без внешних зависимостей.
- `.devcontainer` — среда Flutter для VS Code / GitHub Codespaces.

Заказы передаются через запущенный сервер. GitHub хранит код и не используется в качестве базы данных. Оба приложения должны обращаться к **одному адресу API**. Обновление статусов — опрос каждые 2 секунды.

## Быстрый запуск на компьютере

Требуется Flutter stable с Dart 3.13.3 или новее. Команды выполняются из корня репозитория; для каждого процесса откройте отдельный терминал.

Терминал 1 — API:

```sh
dart server/bin/server.dart
```

Терминал 2 — клиент:

```sh
cd taxi-customers
flutter pub get
flutter run -d chrome --web-port 8080 --dart-define=TAXI_API_URL=http://localhost:8081
```

Терминал 3 — водитель:

```sh
cd taxi-driver
flutter pub get
flutter run -d chrome --web-port 8082 --dart-define=TAXI_API_URL=http://localhost:8081
```

Если Chrome недоступен, используйте `-d web-server --web-hostname 0.0.0.0` вместо `-d chrome` и откройте адрес из терминала в браузере.

При первом запуске сервер добавляет три подписанных демо-заказа. Заказы, созданные клиентом, появляются рядом с ними. Сервер сохраняет данные в `server/data/orders.json` (не коммитится). Чтобы начать с чистой базой, остановите сервер и удалите этот файл. Для запуска без демо-заказов задайте `SEED_DEMO=false` перед первым запуском.

## Codespaces / Dev Container

Откройте репозиторий в Codespaces или выполните **Dev Containers: Reopen in Container**. Скрипт установит Flutter и зависимости. Порты 8080 (клиент), 8081 (API), 8082 (водитель) настроены для проброса.

1. Запустите `dart server/bin/server.dart` из корня.
2. В панели **Ports** скопируйте HTTPS-адрес порта 8081.
3. Запустите приложения командами ниже, подставив этот адрес **без завершающего слеша**:

```sh
# Терминал клиента
cd taxi-customers
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080 --dart-define=TAXI_API_URL=https://YOUR-CODESPACE-8081.app.github.dev

# Отдельный терминал водителя
cd taxi-driver
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8082 --dart-define=TAXI_API_URL=https://YOUR-CODESPACE-8081.app.github.dev
```

Откройте проброшенные 8080 и 8082. Для запросов из разных web-origin Codespaces может потребоваться публичная видимость порта API 8081. Делайте это только на время демонстрации с вымышленными данными: у учебного API нет авторизации. После показа закройте доступ. Открытие только сайта GitHub Pages не запускает Dart-сервер.

## Android и другие устройства

- Android Emulator: `flutter run --dart-define=TAXI_API_URL=http://10.0.2.2:8081`.
- Телефон в той же Wi-Fi-сети: укажите LAN-IP компьютера, например `http://192.168.1.20:8081`. Сервер слушает `0.0.0.0`; разрешите доступ к порту в локальном брандмауэре.
- Для HTTPS-сервера укажите его адрес через тот же `--dart-define`.
- На iOS/macOS для сборки нужен macOS с Xcode. На iOS используйте HTTPS для внешнего API.
- В Android разрешён HTTP для локальной лабораторной. Для публичного приложения нужен HTTPS и более строгая сетевая конфигурация.

`TAXI_API_URL` задаётся при сборке. После изменения адреса перезапустите приложение целиком. Адрес показывается на вкладке профиля. Идентификатор клиента/водителя хранится локально; это позволяет восстановить текущую поездку и историю после перезапуска приложения. Разные браузеры/устройства получают разные идентификаторы.

## Сценарий защиты лабораторной

1. Откройте клиент и водителя с одним API.
2. У клиента нажмите адрес А или Б: выберите место из каталога Иркутска либо «Выбрать точку на карте». Касание карты без открытого выбора меняет назначение.
3. Кнопка с прицелом запрашивает текущую геопозицию: у клиента она меняет подачу, у водителя — его позицию. При отказе в доступе доступен ручной выбор. В web геолокация требует HTTPS или localhost.
4. Выберите «Эконом», «Комфорт» или «Бизнес» и нажмите «Заказать такси».
5. У водителя выберите созданный заказ и нажмите «Принять заказ». Карта покажет путь к подаче.
6. Нажмите «Я на месте», затем «Начать поездку». Карта переключится на маршрут А → Б.
7. Нажмите «Завершить поездку». У клиента заказ завершится после обновления, а у обоих появится в истории. У водителя обновится заработок в кабинете.
8. Дополнительно проверьте отмену до начала поездки и невозможность принять один заказ двумя водителями.

## Карты, маршруты и расчёт

- [OpenStreetMap](https://www.openstreetmap.org/copyright) — онлайн-тайлы с атрибуцией на карте. Интернет обязателен; офлайн-пакеты карт не загружаются.
- [OSRM Route API](https://project-osrm.org/docs/v26.6.1/http.html) — автомобильная геометрия, расстояние и время. Используется публичный демонстрационный сервер без гарантии доступности.
- [geolocator](https://pub.dev/packages/geolocator) — геопозиция устройства по запросу, без фонового трекинга.
- Поиск адресов — локальный каталог мест Иркутска, не глобальный геокодер. Произвольное место выбирается на карте.

Цена: базовая стоимость + стоимость километра, с округлением вверх до 10 ₽. Эконом: 99 + 24/км, Комфорт: 149 + 32/км, Бизнес: 249 + 48/км. Тарифы учебные. Сервер вычисляет сумму из выбранного тарифа и длины маршрута; после заказа цена не меняется.

Если OSRM недоступен, приложение показывает прямую пунктирную линию, оценку расстояния (по прямой × 1.4), времени и цены с явной подписью «примерные». Это не автомобильная навигация. При недоступности тайлов показывается сообщение и кнопка повторной загрузки. При недоступности API заказ не создаётся, приложение сообщает о потере связи и продолжает переподключаться.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка сервера |
| GET | `/orders` | Заказы для водителя |
| GET | `/orders?customerId=…` | Заказы клиента |
| POST | `/orders` | Создание: customerId, pickup, destination, tariff, km, minutes |
| PATCH | `/orders/{id}` | Действие: actorId, action |

Действия: `accept`, `arrive`, `start`, `complete`, `cancel`. Сервер проверяет владельца сессии, последовательность статусов, координаты, расстояние и наличие активного заказа. Один водитель не может одновременно выполнять два заказа. Повторное принятие уже занятого заказа возвращает 409.

Переменные сервера: `PORT` (8081), `TAXI_DATA_FILE` (`server/data/orders.json`), `SEED_DEMO` (`false` отключает начальное заполнение). Сервер предназначен для одного процесса; JSON-файл не подходит для нескольких экземпляров.

## Границы учебного проекта

Реальных вызовов такси, списания денег, GPS-ведения и фонового движения машины нет. Статусы меняет водитель кнопками. Авторизация отсутствует: ID сессии не является защищённым токеном. CORS открыт для лабораторной; API нельзя использовать с реальными персональными данными. Для production нужны аутентификация, права доступа, база данных, HTTPS, свой/коммерческий поставщик карт и маршрутов, серверный расчёт маршрута и мониторинг.
